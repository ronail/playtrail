# Playtrail v1 Worker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build, test, deploy and verify the v1 API in the TRD.

**Architecture:** One Cloudflare Worker in `src/index.ts` writing to one R2 bucket. Tests are black-box HTTP against `wrangler dev` or a deployed URL.

**Tech Stack:** TypeScript, Cloudflare Workers, R2, Wrangler, `node:test` (Node 22).

**Spec:** `docs/superpowers/specs/2026-11-25-v1-worker-design.md` and `docs/TRD.md` (API, CORS, upload sketch, setup).

## Global Constraints

- No runtime dependencies. Dev only: `wrangler`, `typescript`, `@cloudflare/workers-types`, `@types/node`.
- `wrangler.toml` exactly as in TRD "Setup" (bucket `playtrail-logs`, `REGISTER_LIMIT` 5/60, `UPLOAD_LIMIT` 10/60).
- Path regex: `^/v1/logs/([\w-]{1,64})/([\w-]{1,64})$`. Max body: 32 * 1024 bytes.
- CORS headers from TRD "CORS" on every response, including errors.
- Never answer 200/201 unless the object exists.
- Never commit `.dev.vars`.

## Review Focus

All five are pinned by tests in Task 1.

- Missing or non-base64 `X-Signature`: 401, not 500.
- Body over the cap sent without `Content-Length` (streamed): 413.
- Body of exactly 32768 bytes: 201; 32769: 413.
- ID of 65 characters, or containing `%2F` or `.`: 404 with CORS headers.
- Sixth registration within a minute from one address: 429 with CORS headers.

- [ ] **Step 2: Write the failing tests**

Harness in `test/api.test.mjs`:
- Without `BASE_URL`: spawn `npx wrangler dev --port 8787 --var MASTER_KEY:test-only-key`, wait for it to answer, kill it afterwards.
- `register()` → `{client_id, key}`; call it twice in total and share the results (the limit is 5 per minute).
- `put(id, batch, body, {key, signature})` signs `` `${id}\n${batch}\n` `` + body with the **base64-decoded** key.
- `readObject(path)` runs `npx wrangler r2 object get playtrail-logs/<path> --pipe` with `--local`, or `--remote` when `BASE_URL` is set.
- Batch IDs are `crypto.randomUUID()`. Each client sends at most 10 signed uploads (rate limit).

Tests, in this order:

| Test name | Assertions |
|---|---|
| `register returns id and key` | 200; `client_id` is a UUID; `key` decodes to 32 bytes |
| `first upload 201, retry 200, object unchanged` | 201; same batch with a different body → 200; `readObject` equals the first body |
| `bad signature, altered body, other client's id` | each 401 |
| `missing or non-base64 signature` | each 401 |
| `size limits` | empty → 400; 32768 bytes → 201; 32769 → 413 |
| `streamed oversize body` | `ReadableStream` body with `duplex: "half"` → 413 |
| `bad paths` | 65-char ID, `a%2Fb`, `a.b`, unknown route, `GET` on a log path → each 404 with `access-control-allow-origin: *` |
| `cors` | `OPTIONS` → 204 with the four TRD headers; a 401 response carries them too |
| `register is rate limited` | local only (skip when `BASE_URL` is set; the limit is approximate): register until 429, at most 10 tries; the 429 has CORS headers |

- [ ] **Step 3: Run to verify failure**

Run: `npm test`. Expected: FAIL (no `src/index.ts`).

- [ ] **Step 4: Implement `src/index.ts`**

Follow the TRD upload sketch, with these differences:
- `handle(req, env): Promise<Response>` does the routing; the exported `fetch` wraps it in `try/catch` (500) and adds the CORS headers.
- `OPTIONS` → 204. `POST /v1/register` → limit keyed by `req.headers.get("CF-Connecting-IP") ?? "local"` (429), `client_id = crypto.randomUUID()`, `key` = base64 of the HMAC bytes.
- Build the signed message with one `Uint8Array` and `.set()`, not array spread.
- Anything else → 404.

- [ ] **Step 5: Verify**

Run: `npm test && npm run check`. Expected: all tests pass, no type errors.

- [ ] **Step 6: Commit** — `feat: add v1 register and upload worker`
